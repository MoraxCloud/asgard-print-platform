# 仓库 Wiki 同步实施计划

> **给 agentic worker 的说明：** 必需子技能：使用 `superpowers:executing-plans` 逐任务实施。步骤用 `- [ ]` 复选框跟踪。

**目标：** 写 `scripts/sync-wiki.mjs`，把 `docs/guide/` 的索引页 + 10 篇文档同步到 GitHub 与 Gitee 的 Wiki，并实际推送。

**架构：** 脚本读取 guide 目录 → 改写仓库外相对链接为 GitHub 主仓 URL → 生成 Home.md + 10 篇 → 分别推送到两个 Wiki。零第三方依赖。

**技术栈：** Node 内置模块、git、`gh auth token`。

**规格：** `docs/superpowers/specs/2026-11-24-wiki-sync-design.md`

## 全局约束

- 语言：全中文；UTF-8 无 BOM；单次写入不超过 500 行。
- 内容源固定 `docs/guide/`，排除 `AGENTS.md`；`README.md` → `Home.md`。
- 外部链接转 `https://github.com/worm-longliu/worm-print-platform/blob/master/<仓库相对路径>`。
- 脚本零第三方依赖；推送是外部副作用，先 dry-run 验证再实际推送。
- master 直接开发；提交信息中文。

## 审查重点

- 仓库外相对链接残留 → 任务 1 的 dry-run 检查。
- 10 篇页面与 Home 缺失 → 任务 1 的文件数检查。
- 推送到错误仓库/认证失败 → 任务 2 的 ls-remote 校验。
- 两平台内容不一致 → 任务 2 的内容对比。

### Task 1: 编写 sync-wiki.mjs 并 dry-run 验证

**文件：**
- 创建：`scripts/sync-wiki.mjs`

**接口：**
- 产出：`node scripts/sync-wiki.mjs --dry-run` 生成临时目录（Home.md + 10 篇），不推送。

- [ ] **步骤 1：编写脚本**

实现：
- 读取 `docs/guide/README.md` → `Home.md`，`01-*.md`～`10-data-transform.md` → 同名页面（排除 `AGENTS.md`）。
- 链接改写：`](../xxx.md)`、`](../../skills/...)` 解析为仓库根相对路径，转 GitHub blob URL；`./0X-*.md` 与 `./README.md` 保留。
- `--dry-run`：写到 os.tmpdir() 唯一子目录并打印路径，不推送。
- 非 dry-run：GitHub 用 `gh auth token`，Gitee 用 `GITEE_TOKEN` 或默认凭据；分别 clone/init → 覆盖写入 → commit → push。

- [ ] **步骤 2：dry-run 验证**

Run: `node scripts/sync-wiki.mjs --dry-run`
Expected: 打印临时目录；目录含 `Home.md` + 10 篇；`grep -rn '\.\./' <临时目录>` 无仓库外相对链接残留；页内 `./0X-*.md` 链接保留。

- [ ] **步骤 3：提交脚本**

```bash
git add scripts/sync-wiki.mjs
git commit -m "feat: 新增 Wiki 同步脚本"
```
