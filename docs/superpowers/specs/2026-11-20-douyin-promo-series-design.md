# 抖音宣传系列 · 混合推进设计（v1.6.0 基线）

## 一、意图与为什么

当前账号只发布了两支：序章（竖屏机制讲解）与体检报告多页打印（横屏实录）。后者重录后 129.5 秒（` .video-skill/series-roadmap.md:20`），前 3 秒是提问加预告，信息密度按开发者视角堆叠（26 字段、8 表格、107 单元格、`version:1`），抖音播放只有 200。

目的不是把项目讲全，而是让抖音用户在前 3 秒看到结果或冲突，愿意看完并评论。公开复盘资料一致指向：流量主要取决于选题与前 3 秒，工具只负责稳定质量；应盯 2 秒跳出与 5 秒完播，而非单看播放量。

## 二、目标 / 非目标 / 反目标

- 目标：4 周内产出并发布 9 条符合抖音节奏的短视频；建立「2 秒跳出、5 秒完播、平均播放时长、评论/收藏/分享」的复盘表；每条只改一个变量。
- 非目标：不追求把架构讲全；不承诺爆款；不自动上传；不把规划中能力说成已发布。
- 反目标：把 129.5 秒完整实录原样重发；用旧版本口径（v1.5.2 / 「四个包还没发 npm」）发布；低播放就删片重传。

## 三、约束（项目既有事实）

- 流水线与卡片模板冻结在 `.agents/skills/making-douyin-videos/assets/pipeline/`；产物只写 `.video-skill/`，一支一片「日期-主题」目录。
- 封面只用 `cover-douyin.html` 版式，只改 `cover*` 字段；必须交 `cover-douyin-4x3.png` 与 `cover-douyin-3x4.png`。
- 文案恰好 5 条标题（每条 ≤30 字）、5 个不重复标签、置顶评论和不上传的出处表。
- 片尾口播统一为 `endcard-tail.md`「规范口播」，画面卡沿用既有版式；横屏浅色、深色备选。
- 多音字闭环：`pypinyin` 上下文识别 → 人工听审 → 只替换 TTS 文本 → 原文进字幕；未认下的字不得出片。
- 事实口径以最新代码为准：根版本 v1.6.0（2026-11-19，`CHANGELOG.md`）；npm 四包 latest 1.6.0；MCP 12 工具已发布；`docs/proposals/README.md` 六项均为方案草图；`docs/gitee-issues-reproduction.md` 给出 4 条 issue 的真实状态。

## 四、方案对比与选择

| 方案 | 优点 | 代价 |
|---|---|---|
| 只重制旧片 | 成本最低，库存 4 支可直接重剪 | 题材仍是「我们做了什么」，冲突感弱，天花板有限 |
| 只做新片 | 围绕 issue 冲突，钩子强 | 前期产能压力大，账号冷启动期无缓冲 |
| **混合推进（选定）** | 先用体检报告重制验证节奏，再用 3 条真实 issue 冲突型新片建立差异化，库存片穿插；每片只改一个变量便于复盘 | 需要同时维护重剪与新片两条产线 |

## 五、内容设计

### 定位与形式

- 受众：被打印交付折磨的前端与小团队（快递面单、价签、体检报告），不是泛技术观众。
- 新片一律竖屏 1080×1920、15–45 秒；横屏仅用于必须真操作的短片，压到 45 秒内。
- 单条只讲一件事；前 3 秒给结果或冲突；去术语；结尾给边界 + 统一 CTA + 评论引导。

### 片单（4 周，9 条）

### 单条结构

0–3 秒结果/冲突 → 3–10 秒反差并标明「已修复 / 未实现 / 可配置」→ 10–30 秒一条证据（源码行、实测数字、before/after）→ 30–45 秒边界 + 统一片尾 CTA + 评论引导。每条产出剧本、SRT、多音字台账、四张封面、五标签文案、出处表，落一个「日期-主题」目录。

## 六、发布与复盘

- 每周 2–3 条，固定时段，连续 4 周；每条留完整观察窗口。
- 记录：2 秒跳出、5 秒完播、平均播放时长、点赞/收藏/分享、评论；与账号前 10 条中位数对比。
- 迭代：一次只改一个变量（先钩子，再时长，再封面）。低播放不删片，记录原因后用新脚本重做。

## 七、出片前必做

1. 把 `endcard-tail.md`/`endcard-tail.html` 的版本条与所有旧文案从 v1.5.2 升到 v1.6.0 / 2026-11-19；序章旧文案「四个包还没发 npm」不得复用。
2. 每条新片重新核验事实出处、TTS 时长、多音字听审、`check-layout`、`check-subs`、`video:verify`；只改台词必须重跑配音。
3. 转录或重剪旧片时保留原出处表，但更新版本号与事实；库存「from-scratch-废弃」目录须先确认成片可用，否则剔出片单。
4. 不自动上传抖音；发布由用户人工完成，上传前预览平台裁切与读音。

## 八、留给执行阶段的决定

- 具体 `script-<key>.json` 的逐场口播、steps/body、封面 `cover*` 字段与五标签文案，按本设计在 writing-plans 阶段逐条写。
- 重剪旧片是复用 `video_final.mp4` 二次剪辑，还是改剧本整链重跑，按每条的事实更新量决定（版本号变化必须重跑配音与 CTA）。
- 发布时段依据账号后台粉丝活跃时间确定。

## 九、体检报告重制 · 抖音化优化版（本次新增）

针对「提升播放量」的诉求，第 1 条从横屏 129.5 秒完整实录改为**竖屏 1080×1920、约 45 秒**的图文混排讲解片，重点如下：

- **结构改为结果先行**：钩子 3 秒直接甩「五页连出」，不再从「先加载模板」开始；全片只讲一件事——一份模板带格式出五页。
- **图文混排成为主画面**：第三场 `mixed` 用左右分栏，左边列「标题文字 / 表格 / 柱状图 / 折线图 / 合并单元格」，右边画出真实报告页缩略（表格 + 柱状图 + 折线图），把「一页里同时有图和文」做成视觉记忆点。
- **百度图表作为卖点而非背景**：明确柱状图与折线图由 ECharts 插件渲染、不是截图，并用 v1.6.0 的标签偏移修复做 before/after 冲突（`offsetX/offsetY` → `offset:[x,y]`，93 项测试）。
- **口播去术语**：删掉 `version:1` 结构、107 单元格、三条链路细节；只留 5 页 / 26 字段 / 3 图表 / 8 表格四个可举证数字。
- **口径更新**：封面版本条 v1.6.0；片尾口播沿用 `endcard-tail.md` 统一 CTA；标签改为「打印模板 / 体检报告 / 百度图表 / 前端开发 / 开源项目」，把百度图表放进精准长尾。
- **产物**（未配音、未录屏、未出片）：`.video-skill/portrait/script-health-report-remake.json` 与 `.video-skill/portrait/cards-health-report-remake.html`。6 个场景的 `video:portrait:check` 已全绿；后续整链须先更新版本口径、重跑 TTS 与多音字听审。
