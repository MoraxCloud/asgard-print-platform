# 用户使用文档拆分与互跳设计

> 本文是 `2026-11-21-user-guide-split.md` 实施计划的规格来源。经逐项追问收敛，所有决策已明确；未写明的行为沿用仓库现状。

## 1. 意图与为什么

`docs/guide/README.md` 现有 1062 行，单文件过长，读者难以定位章节，也不利于维护。本次把它按现有六章结构拆分——其中「基础接入」再按四框架各拆一份——得到 9 份内容文件；`README.md` 改为索引页，各篇之间像设计器的帮助文档那样可以互相跳转。同时，根 README 快速开始的文案补上 AI 能力的简介与提示词入口，让第一眼读者知道本项目对 AI Agent 友好。

## 2. 目标 / 非目标

- **目标**
  1. 9 份内容文件 + `README.md` 索引页，每份聚焦一个主题。
  2. 索引页列出全部 9 篇及一句话说明；每篇顶部/底部有「上一篇 / 下一篇 / 返回目录」导航。
  3. 根 README 快速开始补 AI 介绍与提示词入口链接。
  4. 修正所有因拆分而失效的链接与测试读取路径，不留断链/失效锚点。
- **非目标**
  - 不改变文档正文内容（含 AI 提示词），只做拆分、导航与入口文案调整。
  - 不新建在线文档站；访问方式仍是仓库网页。
  - 不改动任何运行时代码（测试路径常量除外）。

## 3. 约束

- 语言：全中文；UTF-8 无 BOM；单次写入不超过 500 行（单篇最大约 500 行，无需再拆）。
- 现有测试 `packages/core/src/i18n/__tests__/docs.spec.ts` 的 8 个 API 词断言必须仍通过，读取路径需改指拆分后的多语言文件。
- 所有相对链接必须解析到真实存在的文件；所有文内锚点必须对应实际标题。
- 提交信息中文；在 master 直接开发（AGENTS.md）。

## 4. 方案（Approaches）

1. **保持单文件**：不满足拆分诉求，放弃。
2. **按六章拆 6 份**：粒度较粗，基础接入仍是一份大文件——用户选择更细粒度。
3. **按六章 + 四框架各拆一份，共 9 份 + 索引页**（**选定**）：与帮助文档的章节化结构对齐，单篇聚焦、链接稳定，代价是文件数增多、需逐处修正引用。

## 5. 文件映射（原文 → 新文件）

| 新文件 | 来源章节 | 体量 |
| --- | --- | --- |
| `README.md` | 原六章目录 → 重写为索引页 | 短 |

拆分时各文件保留一个一级标题（如 `# Vue 3 接入`），原 `### 2.1` 等编号前缀去掉，正文、代码块、表格、AI 提示词原样保留。

## 6. 导航设计

- `README.md` 索引页：标题 + 一句话定位 + 9 个链接（带一句话说明），按上表顺序。
- 每篇顶部放一行导航条：`← 返回目录 | ← 上一篇：<标题> | 下一篇：<标题> →`（首尾篇缺项则省略）。
- 每篇底部重复该导航条，首尾呼应，仿帮助文档的章节切换体验。
- 顺序：README → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09。

## 8. 验证

1. `npm test`，重点确认 `docs.spec.ts` 通过。
2. 相对链接解析脚本：遍历 `docs/guide/*.md` 与所有被改的 README，确认每个 `](./...)` / `](../...)` 目标存在。
3. 锚点检查：文内 `#锚点` 均对应实际标题。
4. 导航条检查：9 篇均有顶部/底部导航，链接文件名存在。
5. `git diff --check` 与 `git diff` 审查。

## 9. 留给我（实施者）的判断

- 各篇一级标题用简短中文（如 `# Vue 3 接入`、`# 多语言配置与自定义`），去掉原 `2.1` 等编号前缀；正文小标题层级整体上移一级或保留，以链接可达为准。
- 索引页每篇的一句话说明从原章节首段提炼，不新造内容。
- 导航条用纯 Markdown 链接，不引入 HTML；首尾篇缺少的方向省略。
- 若某篇拆出后顶层标题与内容标题重复，合并为一个标题。
