安全链路：AI 不直接写画布。所有变更走 template.apply → revision 冲突拒绝 → 封禁元素校验 → 结构校验 → 写回，与桌面 MCP 完全同口径。

设计要点（与现有代码的衔接）

  1. UI 落点：在 packages/canvas 右侧属性面板增加第四个页签「AI 助手」，不改动中间画布与左侧字段树的既有交互。
  2. 连接层：复用 demos/shared/template-session.ts 已验证的状态机（unreachable / idle / attached）与 revisionOf() 内容指纹；会话状态和 revision 短码直接显示在面板状态条。
  3. 写回链路：模型输出的模板 JSON 不直接落到画布，而是作为 template.apply 请求进入现有 handler：先校验 baseRevision 一致性（冲突拒绝），再走 findBlockedElementPaths 封禁元素校验与结构校验，最后 structuredClone 写回并由画布重读新 revision。
  4. 可审阅 / 可撤销：每次 apply 返回新旧 revision 与元素级 diff 统计，渲染为对话内的「变更摘要卡」；撤销按钮复用设计器既有撤销栈（onApplyResult('success') 已提示可撤销）。
  5. 模型归属：遵循现有技能约定——面板不持有模型密钥，通过宿主注入的模型适配器调用（对应功能 03 的可插拔传输）。
依赖：功能 03（统一会话 SDK）提供连接层，功能 02（MCP 流式）提供逐步进度与提示词；本功能本身是面向用户的表现层。
