浏览器直连 AI 通道与统一模板会话 SDK

当前 AI 通道必须依赖桌面客户端 + 配对 token + 外部 MCP 客户端，且模板会话在四个 demo 中各自内联实现（jQuery 版还只能只读）。本方案新增公开 SDK @worm-print-platform/ai-session，把「连接 / revision / 写回校验」收敛为一层，并提供三条可插拔传输链路。

三条接入链路（同一套 SDK，传输可插拔）

① 浏览器直连

新增
设计器（canvas）
↓
ai-session SDK · SSE 传输
↓
宿主配置的模型端点
↓
工具循环：template.get / apply
无需 Electron；密钥由宿主服务端代理下发短期令牌，浏览器不落地长期密钥。

② 服务端代理

新增
设计器（canvas）
↓
ai-session SDK · HTTP 传输
↓
render 服务 /ai/chat
↓
模型密钥不暴露给浏览器
复用渲染服务部署；适合企业内网、密钥集中管理与审计。

③ Electron MCP

现状
设计器（canvas）
↓
PrintClient · WebSocket
↓
桌面 MCP（12 工具）
↓
外部 Agent / 模型
保留兼容：现有桌面静默打印与配对鉴权链路不动，SDK 作为统一的会话门面。
SDK 接口示意（与 template-session.ts 同口径）
// @worm-print-platform/ai-session —— 连接层与校验层统一，模型/密钥归宿主 import { createAISession, createTransport } from '@worm-print-platform/ai-session' const transport = createTransport('sse', { endpoint: '/ai/chat' }) // 'ws' | 'sse' | 'http' const session = createAISession({ transport, snapshot: () => ({ templateJson, fields, printData }), // readSnapshot apply: (json, baseRevision) => canvas.write(json, baseRevision), // 写回钩子 onStatus: (s, err) => badge.update(s, err), }) session.start() // attach + 建立传输 + 订阅 SSE delta / progress session.ask('把表头改成蓝色') // 工具循环自动执行 template.get → apply // 内置：revisionOf / createRevisionCache / 封禁元素校验 / 结构校验 // 与 demos/shared/template-session.ts、packages/mcp 完全同口径
收敛重复实现

  • demos/apps/jquery/src/mcp-session.js（仅只读）
  • demos/shared/template-session.ts（仅客户端集成测试复用）

目标：1 个公开 SDK + 4 个宿主薄适配

  • 新增 packages/ai-session（随 npm 发布）
  • 各 demo 只保留「读画布 / 写画布」两个钩子
  • jQuery 版同样获得写回能力（同一 revision 校验）
  • 功能 01 的面板直接依赖 SDK，不再复制连接代码

设计要点（与现有代码的衔接）

  1. 抽取来源：以 demos/shared/template-session.ts 为实现蓝本——状态机、6 位 sessionId、revisionOf() 键排序 SHA-256、createRevisionCache()、template.get / template.apply handler 全部平移进 SDK。
  2. 传输抽象：createTransport('ws' | 'sse' | 'http') 对应功能 02 的三种链路；WS 复用 PrintClient，SSE 复用新增的 /mcp/events，HTTP 走服务端代理。
  3. 安全：SDK 不持有模型密钥；浏览器直连场景由服务端下发短期令牌，沿用现有 Bearer pairing token 鉴权口径。
  4. 兼容：桌面 MCP 12 工具与 template.attach/get/apply/detach 消息类型保持不变，四个 demo 仅做几行初始化替换，不重写业务逻辑。
  5. 发布：新增包加入 publish:npm 列表，纳入 core → 宿主的分层边界（只依赖 core，不引入 Vue/React）。
被依赖：功能 01 的连接层、功能 02 的 SSE 传输都需要本 SDK 提供统一入口；建议作为第一步实施。
