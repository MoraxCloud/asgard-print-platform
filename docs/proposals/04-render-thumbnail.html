设计要点（与现有代码的衔接）

  1. 复用管线：services/render/src/server.ts 现有 POST /render/pdf 已经用 Playwright 打开渲染页并注入 templateJson + printData；PNG 仅在最后一步把 page.pdf() 换成 page.screenshot()，分页与数据绑定逻辑零改动。
  2. 缩放与裁剪：scale 控制设备像素比，clip 支持整页 / 页眉 / 指定元素，既服务缩略图墙也服务 AI 的「只看这一块」审阅。
  3. 缓存：以模板内容 revision 作为缓存键（与 revisionOf() 同口径），模板一变自动失效，避免缩略图墙反复出图。
  4. 流式兼容：缩略图结果可作为 MCP resource preview://page1 暴露（功能 02），AI 会话直接引用。
  5. 契约一致：沿用现有 10MB / 30s / 500 份限制与错误响应格式，Docker 部署与 /health 不变。
被依赖：功能 01 的「预览结果」按钮与功能 06 的版本差异缩略图都调用本接口；与 PDF 链路平行，不改动三端打印主流程。
