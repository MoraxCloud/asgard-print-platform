真实 Excel / Word 导出插件与宿主菜单

导出插件注册表 export-plugin-registry.ts 已用 Symbol.for 实现跨 bundle 单实例，但 marketplace.json 的 exportFormats 全空、没有真实插件，设计器也没有导出入口。本方案补上插件与菜单，打通「设计 → 多格式交付」闭环。

安装
安装方式：沿用 worm-print-marketplace 四源 CLI；插件声明 exportFormats 后自动出现在设计器导出菜单。

导出数据流

设计器导出菜单→ export-plugin-registry（Symbol.for 单实例）→ 插件渲染器：表达式求值 + 元素映射→ 生成 xlsx / docx→ 浏览器下载 / 客户端落盘

设计要点（与现有代码的衔接）

  1. 复用注册表：packages/core/src/designer/export-plugin-registry.ts 已经实现（`Symbol.for` 跨 bundle 单实例），本功能不重写注册表，只新增符合契约的插件实现并在 marketplace.json 声明 exportFormats。
  2. 数据一致性：导出前调用 core 表达式引擎对模板求值，保证 xlsx / docx 中的金额、日期、合计与 PDF / 打印结果一致，不依赖 Excel / Word 自身计算。
  3. 宿主接入：在 packages/canvas 顶栏增加「导出」菜单，菜单项由注册表动态生成（PDF / PNG 为内置，其余来自已安装插件）。
  4. 边界：遵循现有市场边界——不做沙箱、不做市场静态站点；插件作为 npm 包安装并声明导出格式即可。
  5. 与功能 04 协同：PNG 作为内置导出项复用缩略图 / 截图接口，和插件导出共用同一个菜单入口。
独立功能：不依赖 AI 会话，但扩展了整体交付形态；可与功能 04 的 PNG 导出一并实施。
