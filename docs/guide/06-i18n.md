# 多语言配置与自定义（i18n）

[← 返回目录](./README.md) | ← 上一篇：[jQuery / 原生 JS 接入](./05-jquery.md) | 下一篇：[插件安装与配置](./07-plugin-install.md) →

> **目标**：一份扁平点号键 JSON（flat dot-key JSON），让浏览器设计器、render 服务、桌面客户端同时显示自定义语言。
> **路线**：导出骨架 → 翻译 → 校验 → 人工审核 → 三端接入 → 运行时切换 → 排错。
> **配套技能**：`worm-print-platform-i18n`（安装见 [01 开始之前](./01-getting-started.md#32-官方技能skills)）。没有技能环境时，直接复制本文 §3.6 的 AI 提示词。
> **前置**：已完成 [01](./01-getting-started.md)，有一个已 npm 安装 `@worm-print-platform/*` 的项目；目标语言用 BCP47 标签（如 `ja-JP`）。

## 3.1 先看结论：能力边界与总体架构

- **内置三语**：`zh-CN`（源语言）、`en-US`、`th-TH`，随包发布、零配置。
- **自定义整包**：任意 BCP47 标签（如 `fr-FR`、`ja-JP`），由宿主提供扁平点号键 JSON（键自带命名空间前缀，如 `constants.borderStyle.none`）。
- **缺键回退**：已登记键在目标语言缺失或为空串时回退 `zh-CN`；**从未登记过的新键**在运行时最终返回 key 本身（开发态 `console.warn`）。因此必须用 `template` 出骨架、`validate` 拦截，不要手写键。
- **固定检索链**：`user`（宿主/实例）→ 各插件 id → `constants` → `propertyTips` → `core`。
- **不在范围内的内容**：帮助弹窗正文只覆盖内置三语，自定义语言回退中文正文；页面名、示例单元格等模板数据属于业务数据，不翻译。
- **一套引擎**：core 依赖 `i18next` 做薄封装（`@worm-print-platform/core/i18n`），各包只依赖 core 的 i18n 子路径。

```
                   ┌──────────────────────────────────────────┐
                   │       @worm-print-platform/core/i18n      │
   t() / createTranslator(locale, messages?) / setLocale() ...
                   │       i18next 实例（薄封装 engine.ts）     │
                   └──────────────────┬───────────────────────┘
                                      │ resourceStore
    user（宿主/实例） → 插件 id → constants → propertyTips → core
   registerLocale / el.messages   语义键资源（JSON 真源）
```

## 3.2 生成语言包：骨架 → 翻译 → 校验 → 审核

### 3.2.0 前置条件与命令位置

在项目根目录执行。**关键前置**：`<项目根>` 必须是一个已 `npm install @worm-print-platform/*` 的项目（CLI 从它的 `node_modules` / `.worm-print/i18n` 发现资源）；`<项目根>` 默认 `process.cwd()`，可用 `--dir` 覆盖。注意 `-o` 输出路径相对**当前 cwd**，与 `--dir`（资源发现根）是两个不同概念。

```bash
npx @worm-print-platform/i18n template -o fr-FR.json
npx @worm-print-platform/i18n validate fr-FR.json --strict
npx @worm-print-platform/i18n update fr-FR.json
npx @worm-print-platform/i18n report fr-FR.json -o fr-FR-comparison.md
```

- CLI 也可写作 `worm-print-i18n <命令>`（包名 `@worm-print-platform/i18n`，零运行时依赖，正式发布包之一）。
- 退出码：`0` 成功 / `1` 校验失败 / `2` 用法错误。
- **npx 失败时的排查与回退**：`@worm-print-platform/i18n` 是正式发布包，但 `npx` 可能因为「镜像源未同步 / 网络受限 / 本地未安装」返回 404。按顺序排查：① 确认 registry（公司镜像可能滞后）；② 项目 `node_modules` 已装该包时用 `npx --no-install @worm-print-platform/i18n <命令>`；③ 仍失败则用仓库源码 CLI，**从仓库根目录**执行，并显式把资源发现根指到已装包的项目：`node packages/i18n/dist/cli.js template -o /绝对路径/fr-FR.json --dir <已装包项目根>`。`--dir` 必须指向已 `npm install` 的项目（仓库根本身也可），否则骨架会是空 `{}`。**404 不等于命令写错**，先判因再回退。
- 资源发现顺序：`<项目根>/.worm-print/i18n/<id>/<locale>.json`（市场安装，优先）→ `<项目根>/node_modules` 下声明 `wormPrint.i18n` 的包（npm 直装，按 `wormPrint.id` 去重）。旧市场安装缺少 `i18n` 字段时输出「插件 X 的语言资源未同步，请重新安装」。`canvas` / `plugin-kit` 不产出语言资源。

### 3.2.1 导出骨架

```bash
npx @worm-print-platform/i18n template -o fr-FR.json --dir .
```

骨架是**扁平对象**，键自带命名空间前缀，值为中文源文；排序为 core → constants → propertyTips → 插件 id 字母序，同组内按键字母序，2 空格缩进 + 末尾换行。示例：

```json
{
  "toolbar.save": "保存",
  "constants.borderStyle.none": "无",
  "propertyTips.ap-img-fit": "图片适应方式",
  "echarts.panel.chart": "图表"
}
```

### 3.2.2 翻译硬约束

- 只改 `value`，不动 `key`；禁止 `_meta`、嵌套对象、非字符串值。
- 值必须是**非空字符串**：空串会被 `validate` 判错，运行时按缺失回退中文（`returnEmptyString: false`）。
- `{pos}`、`{value}` 等占位符的数量与名称必须与中文一致；文案里的 HTML 原样保留。
- 骨架里的值是中文源文，`validate --strict` **只查格式，不查是否已经翻译**。翻译完成前不要把它当成合规语言包；用 3.2.4 的对照表做人工审核。
- 中文文案只存语言资源 JSON，不要往 core 常量里再写一份中文（双真源会漂移）。

### 3.2.3 校验

```bash
npx @worm-print-platform/i18n validate fr-FR.json --strict --dir .
```

| 问题 | 级别 |
| --- | --- |
| 缺键、空值、占位符不一致、`_meta`、非字符串值 | error（退出码 1） |
| 多余键 | 默认 warn；`--strict` 升为 error |

### 3.2.4 生成对照表并人工审核

```bash
npx @worm-print-platform/i18n report fr-FR.json -o fr-FR-comparison.md --dir .
```

对照表契约：中文列在最左，其后依次是 en-US、th-TH、目标语言列，最后一列是「使用位置」（`相对路径:行号`，源码优先，最多 3 处，找不到显示 `—`）；按模块分组，core 按 key 首段（如 `core / toolbar`），常量为「常量 constants」，属性说明为「属性说明 propertyTips」，插件为「`<id> / <第二段>`」（如 `echarts / panel`）；单元格里的 `|` 转义为 `\|`，换行压成空格。

人工审核重点：中文列是否为空、占位符是否丢失、目标语言列是否残留中文、使用位置是否指向正确模块。

- **「残留中文」的判定**：对英语等拉丁字母语言，看目标列是否仍有汉字即可；但对日语、韩语等含汉字词的语言，很多正确译文与中文同形（如「保存」「プレビュー」中的汉字），肉眼容易误判。建议改用机读辅助：确认目标值与中文源文**不完全相同**（或有假名/谚文等目标文字）即视为已译，再对同形词做抽样人工确认。
- **使用位置**：生成器优先列源码引用点；译文定义文件（`messages/*-*.ts`）不是主要引用位置，出现时仅作参考。审核时以「使用位置是否指向正确模块」为辅，主要看译文本身是否正确。

### 3.2.5 依赖升级后用 update（不要重新 template）

```bash
npx @worm-print-platform/i18n update fr-FR.json --dir .
npx @worm-print-platform/i18n validate fr-FR.json --strict --dir .
```

- `update` 保留已有译文、补新增键为空串；`--prune` 删除骨架中已不存在的键。写回前按骨架顺序排序。
- `update` 后立即 `validate` 报新增空值是**预期行为**：它提示待翻译项，填完再校验。
- 换语言或从零重做才重新 `template`（会覆盖目标文件）；已有人工修订用 `update`，避免被覆盖。

## 3.3 接入与切换：三端运行时

### 3.3.1 浏览器设计器：全局共享 vs 单实例隔离

```ts
// A 全局注入：多个实例共享一份语言包
import { registerLocale, setLocale } from '@worm-print-platform/core/i18n'
registerLocale('fr-FR', frPack)   // 上一步生成的扁平 JSON
setLocale('fr-FR')                // 运行时切换，立即生效

// B 单实例隔离：只作用于当前设计器，不写全局
const el = document.querySelector('print-designer')
el.lang = 'fr-FR'
el.messages = frPack
el.setLocale('fr-FR')             // 运行时切换并立即重绘
```

`<print-designer>` 契约：`lang` attribute/property 为界面语言（BCP47，缺省按 `navigator.language` 探测、回退 `zh-CN`）；`messages` 仅接受对象，是实例级语言包，覆盖内置与插件译文、缺键回退中文；`setLocale(locale)` 运行时切换。未显式设置 `lang` 的实例跟随全局 locale。

宿主差异（i18n 加载与切换本身是框架无关的）：

| 宿主 | 写法 |
| --- | --- |
| Vue 3 门面 | 从 `@worm-print-platform/canvas/vue3` 导入 `PrintDesigner`，传 `lang` / `messages` props（同名，见 [02 §2.3](./02-vue3.md#23-组件契约component-contract)） |
| Vue 2 / React / jQuery（原生 `<print-designer>`） | 在元素创建后对其设置 `lang` / `messages` property；完整接入见对应指南 |

Vue 3 门面最小语言包示例（可直接复制，`jaPack` 为 [3.2](#32-生成语言包骨架--翻译--校验--审核) 生成的 JSON）：

```vue
<script setup>
import { ref } from 'vue'
import { PrintDesigner } from '@worm-print-platform/canvas/vue3'
import jaPack from './ja-JP.json'

const fields = ref([
  { fieldKey: 'order.no', fieldLabel: '单号', fieldType: 'string', sortOrder: 1 },
])
</script>

<template>
  <PrintDesigner :lang="'ja-JP'" :messages="jaPack" :fields="fields" :is-edit="true" />
</template>
```

> 门面会把 `lang` / `messages` props 转赋到内部 `<print-designer>` 的 property（源码 `packages/canvas/src/vue3/PrintDesigner.ts`），等价于原生写法的实例隔离，不写全局。
> `lang` 指定界面语言与语言包，`setLocale(locale)` 用于运行时立即切换并重绘；原生元素上二者都可用（`el.lang='ja-JP'` 设定、`el.setLocale('ja-JP')` 立即切换）。

已知限制：未使用 `ctx.t` 的第三方插件 UI 仍跟随全局 locale，不随实例语言变化；帮助弹窗正文与页签不做自定义语言（见 3.5）。

### 3.3.2 render 服务：环境变量

- `WORM_PRINT_LOCALE`：诊断语言，默认 `zh-CN`；`en-*` 归一到 `en-US`，`th-*` 归一到 `th-TH`，其余保持原值并靠缺键回退中文。
- `WORM_PRINT_LOCALE_FILE`：扁平键 JSON 路径（绝对路径或相对进程 cwd）。启动时先 `setLocale`，再读取并 `registerLocale`；文件缺失 / JSON 非法 / 值非字符串时 `console.warn` 并继续启动。

完整可复制示例（当前目录下的 `locales/fr-FR.json` 挂载进容器）：

```bash
# cwd = 你的项目根，先确保 ./locales/fr-FR.json 存在
docker run --rm -p 3001:3001 \
  -e WORM_PRINT_LOCALE=fr-FR \
  -e WORM_PRINT_LOCALE_FILE=/app/locales/fr-FR.json \
  -v "$(pwd)/locales:/app/locales:ro" \
  worm-print-platform-render:latest
```

> `worm-print-platform-render:latest` 是本地镜像，在仓库根构建（镜像名不同则替换上方命令）：
>
> ```bash
> # cwd = 仓库根
> docker build -f services/render/Dockerfile -t worm-print-platform-render .
> ```
>
> 仅改语言路径时不必改 `-p` 端口。若未部署 render 服务，跳过本节。

### 3.3.3 桌面客户端：config.json + 内置兜底

配置文件位于 Electron 的 `userData/config.json`。`userData` 是各系统应用数据目录，典型位置：

| 系统 | 典型路径 |
| --- | --- |
| macOS | `~/Library/Application Support/WormPrintClient` |
| Windows | `%APPDATA%\WormPrintClient` |
| Linux | `~/.config/WormPrintClient` |

> 准确路径以客户端实际 `app.getPath('userData')` 为准：安装包版本的产品名为 `WormPrintClient`（上表）；开发态 Electron 目录名可能是包名 `worm-print-platform` 或 `@worm-print-platform`，绿色版则用 `WormPrintClient`。找不到时看客户端日志启动行，或在安装/用户目录搜 `config.json`。

`userData/config.json`：

```json
{ "locale": "fr-FR", "localePack": "packs/fr-FR.json" }
```

- `locale` 为空跟随系统；`localePack` 为绝对路径或相对 `userData` 的路径（上例即 `<userData>/packs/fr-FR.json`）。
- `localePack` 为空时回落应用内 `out/locales/<locale>.json`（随包发布）。启动顺序：加载 config → `setLocale` → 加载语言包 → 初始化打印引擎；失败写日志 warn 并回退内置语言，不阻塞启动。
- 新语言要么放进仓库根 `locales/` 后重新打包（`node clients/client/scripts/copy-locales.mjs` 复制到应用内），要么填 `localePack` 后重启。

**统一发现约定**：显式配置（env / config.json / 浏览器宿主代码）优先；未配置时回落应用根 `locales/<locale>.json`。

### 3.3.4 切换与验证

- 全局：`setLocale('fr-FR')` 切换，`setLocale(null)` / `resetLocale()` 回到探测结果，`getLocale()` 读取当前语言，`subscribe(listener)` 监听变化。
- 实例：改 `el.lang` 即可；`el.messages` 只影响该实例。
- API 验证：调用 `t('toolbar.save')` 确认命中译文，用 `getMissingKeys()` 看开发态缺键 warn；界面不应出现 `echarts.panel.overflow.default` 这类裸 key。

**可见验收点（决定是否真的生效）**：

1. 设计器：工具栏「保存 / 预览」等按钮文案变为目标语言；切回 `zh-CN` 恢复中文。
2. 属性面板：带 `labelKey` 的选项（边框线型、水印密度等）显示目标译文，不是硬编码中文或裸 key。
3. 控制台：无 `missing key` 的 `console.warn`（开发态）。
4. render：设置 `WORM_PRINT_LOCALE` 后，诊断信息/外壳文案为目标语言；PDF 正文的 `<html lang>` 由模板 `documentLang` 控制，不随 UI 语言变化（见 3.5）。
5. client：配置 `locale` 并重启后，外壳文案切换；失败时日志 warn 并回退内置语言、不阻塞启动。

## 3.4 内核与资源契约（按需读）

### 3.4.1 资源目录与包声明

```
packages/core/src/i18n/
  messages/                       core 消息 TS（诊断/校验/服务/外壳/表达式）
  locales/constants-{zh-CN,en-US,th-TH}.json    常量三语真源
  locales/propertyTips-{zh-CN,en-US,th-TH}.json 属性说明三语真源
  locale-keys.json               由 TS + JSON 合并派生的语义键清单
packages/core/dist/i18n/<locale>.json   构建后由 getResources() 生成（不手写）
marketplace/plugins/echarts/src/i18n/<locale>.json   插件语言资源（JSON 真源）
marketplace/plugins/echarts/dist/i18n/<locale>.json  构建产物
dist/i18n/resources.json         根 bundle 快照
```

包内声明（`core` 的 id 是 `core`，`echarts` 的 id 是 `echarts`）：

```json
{ "wormPrint": { "id": "core", "i18n": { "dir": "dist/i18n", "base": "zh-CN" } } }
```

`dist/i18n/<locale>.json` 顶层是命名空间，第二层是扁平键，值为字符串：

```json
{ "echarts": { "echarts.panel.chart": "图表", "echarts.series.typeNames.bar": "柱状" } }
```

core 文件含 `core` / `constants` / `propertyTips` 三个命名空间；插件文件只含自身命名空间。**插件必须提供 `zh-CN`**，`en-US` / `th-TH` 可选；插件命名空间 = `wormPrint.id`，必须与注册 `ElementUI` 时的 `i18nId` 一致。

### 3.4.2 语言归一与 i18next 配置

`normalizeLocale(input)`：非字符串 / 空串 → `zh-CN`；`/^en([-_]|$)/i` → `en-US`；`/^th([-_]|$)/i` → `th-TH`；其余（如 `fr-FR`、`ja-JP`）原样保留。`detectLocale()` 取 `navigator.language` 并归一，异常回退 `zh-CN`。

| 配置 | 值 | 原因 |
| --- | --- | --- |
| `keySeparator` | `false` | key 含点（`constants.borderStyle.none`），必须当扁平键 |
| `nsSeparator` | `false` | 不用 `ns:key` 前缀语法，命名空间靠 ns 数组检索 |
| `interpolation` | `{ prefix:'{', suffix:'}', escapeValue:false }` | 兼容 `{name}` 插值；文案含 HTML 不能被转义 |
| `fallbackLng` | `zh-CN` | 缺键与空串回退中文源文本 |
| `returnEmptyString` | `false` | `update` 写入的空值在运行时按缺失回退 |
| `defaultNS` | `core` | 内置核心资源所在命名空间 |

### 3.4.3 对外 API

`@worm-print-platform/core/i18n`（主入口亦 re-export）：

- 状态：`setLocale(locale|null)`、`resetLocale()`、`getLocale()`、`subscribe(listener)`、`normalizeLocale(input)`
- 翻译：`t(key, params?)`、`translate(locale, key, params?)`、`createTranslator(locale, messages?)`
- 注入：`registerLocale(locale, messages)`、`mergeLocale(locale, partial)`、`registerPluginMessages(locale, pluginId, messages)`
- 诊断：`getMissingKeys()`、`clearLocales()`（只清 user 与插件层，不动内置三命名空间）、`getResources(locale?)`
- 类型：`Locale`、`Translate`、`LocaleMessages`、`CustomLocaleMessages`、`PluginLocaleMessages<Id>`
- 格式化：`formatNumber(value, locale, options)`、`formatDate(value, locale)`

插值用法：`t('toolbar.save')`；`t('diagnostic.position', { pos: 3 })` 对应文案 `位置 {pos}: ...`。

`createTranslator(locale, messages?)` 与实例隔离：不传 `messages` 时按全局引擎取词；传入时为该对象创建独立 i18next 实例（WeakMap 缓存），只承载 `user` 命名空间，**用户包命中优先，缺键/空串回退全局**。`el.messages` 不写全局，不会污染其他实例或全局 `t()`；多实例共享一份包用全局 `registerLocale`。

### 3.4.4 常量与属性说明

纸张预设、边框线型、水印密度、内容标签与边框长提示都是语义键资源，中文文案只存 `constants-*.json`：

- `PAPER_PRESETS` 条目用 `labelKey`（如 `constants.paper.A4.label`）与 `group`（`common|dotMatrix|labels|receipt|continuous`）；分组显示键 `constants.paper.group.*`。
- `BORDER_LINE_STYLES` 用 `labelKey`（如 `constants.borderStyle.none`）；水印密度用 `constants.watermark.density.*`；提示用 `constants.hint.border.apply|pending|multi|mixed`。
- `PROPERTY_REGISTRY` 项用 `tipKey`（如 `propertyTips.ap-img-fit`，共 18 条）；`propertyTip(key)` 保留兼容导出，固定以 zh-CN 取词。
- canvas 统一走 `tr(ctx, labelKey)` / `tr(ctx, tipKey)`；属性搜索分组标签与中文关键词只参与匹配、不显示。

### 3.4.5 插件多语言

```ts
import { defineElementUI, registerElementUI } from '@worm-print-platform/plugin-kit'
import type { PluginLocaleMessages } from '@worm-print-platform/core/i18n'

// 插件必须提供 zh-CN；en-US / th-TH 可选。各自从 src/i18n/<locale>.json 取「id 层」扁平对象
const zh: PluginLocaleMessages<'myplugin'> = { 'myplugin.title': '我的插件' }
const en: PluginLocaleMessages<'myplugin'> = { 'myplugin.title': 'My Plugin' }
// const th: PluginLocaleMessages<'myplugin'> = { 'myplugin.title': 'ปลั๊กอินของฉัน' }
registerElementUI(defineElementUI({
  types: ['myElement'],
  renderCanvas: () => '',
  i18nId: 'myplugin',                       // 命名空间 id = 键前缀
  locales: { 'zh-CN': zh, 'en-US': en },    // 有 th 时再加 'th-TH': th
}))
```

`registerElementUI()` 对每个 locale 调 `registerPluginMessages(locale, pluginId, messages)`：键必须以 `${i18nId}.` 开头（强校验），按插件 id 注册命名空间并加入检索链，返回 dispose 句柄供注销清理。插件除 `ElementUI.locales` 外还需声明 `wormPrint.i18n` 并产出 `dist/i18n/<locale>.json`。

**不要在模块加载期把译文求值成常量**：控件文本用 `ctx.t` 或 `t()`（渲染时取词）；导出常量存 key（如 `labelKey`），用 getter 取词。`echarts` 插件即采用此模式，其 `src/i18n/{zh-CN,en-US,th-TH}.json` 各 149 键。用户包可覆盖插件译文：`mergeLocale('en-US', { 'myplugin.title': 'Custom Title' })`。

### 3.4.6 内置语言开发与 bundle

1. 新增语言：core `messages/` 加 `{locale}.ts`、`shell-*` / `expr-*`，键与 zh 一致；`constants-*.json` / `propertyTips-*.json` 加对应语言；插件 `locales` 加该语言（必须含 zh-CN）。
2. 帮助文档加 `help-content/{locale}/` 六章节并在 `index.ts` 加分支。
3. `npm run i18n:keys -w @worm-print-platform/core` 重生成 `locale-keys.json`；`npm run i18n:check -w @worm-print-platform/core` 校验三语 parity；全量 `npm test`。

`npm run i18n:bundle`（前置 `npm run build`）从各包 `dist/i18n/*.json` 导出 `dist/i18n/resources.json` 与 `resources.js`（`export const resources`），结构为 `{ [locale]: { core, help, constants, propertyTips, echarts } }`。`help` 是**静态内容快照，不参与运行时取词**；某插件 `dist/i18n` 缺失时打印 warn 并跳过。自建 i18next 时须设 `keySeparator: false`、`nsSeparator: false`、`interpolation: { prefix:'{', suffix:'}', escapeValue:false }`、`fallbackLng: 'zh-CN'`。

## 3.5 排错与已知限制

| 症状 | 原因 / 处理 |
| --- | --- |
| 显示 `echarts.panel.overflow.default` 等裸 key | 插件包是旧构建：模块加载期求值 + 只用全局 `t`，晚于 `registerElementUI` 注册。重建插件并同步副本，确认 `ctx.t` / `withTranslator` 存在 |
| 切 en-US 后属性面板仍中文 | 插件 UI 没用宿主注入的 `ctx.t`，只用了全局 `t`；示例级 `el.lang` 不改全局 locale |
| 缺键但显示中文 | 回退链生效（`fallbackLng: 'zh-CN'`）；用 `validate` 找缺键，不要靠肉眼 |
| 中文列为空 | 对照表首列取 `values['zh-CN']` 未映射；重新生成对照表 |
| 颜色 / 线型选项是中文 | 常量用了硬编码 `label` 而非 `labelKey`；改用 `t(preset.labelKey)` |
| 水印密度显示 `Dense（200×120）` | 尺寸后缀括号写死；用 `constants.watermark.density.size` 按语言取词 |
| 完全未登记的 key 显示成 key 本身 | 引擎最终兜底返回 key；用 `template` + `validate --strict` 保证所有展示文案都在骨架里 |

其他限制：帮助正文含 HTML 且用 `innerHTML` 渲染，自定义语言只保证外壳标题与关闭按钮可翻译，页签与正文仍中文（已接受限制）；未使用 `ctx.t` 的第三方插件 UI 只跟随全局 locale。

保持不变的业务语义：

- **人民币大写**（`toUpperCaseAmount`）始终输出中文大写金额，不随 locale 变化。
- 打印 HTML 的 `<html lang>` 由 `GenerateOptions.documentLang` 控制（默认 `zh-CN`），**不随 UI 语言变化**——文档语言属于模板内容。
- 关系型数据整形工具 `reshapeRelationalData` 与多语言无关。

校验与排查工具：

- `npm run i18n:keys -w @worm-print-platform/core` / `npm run i18n:check -w @worm-print-platform/core`：生成 / 校验 `locale-keys.json`（含三语 parity）。这两个脚本定义在 core workspace，根目录没有同名脚本。
- `npm run i18n:bundle`：导出聚合资源；`npm run verify:i18n:full`：build + 全量 test + bundle + 一键校验。
- `node scripts/check-hardcoded-zh.mjs <dir...>`：扫描残留硬编码中文 UI 文案（跳过注释与语言包）。
- `getMissingKeys()`：开发模式缺键 `console.warn`，仅当 fallback 也缺才计入。
- 回归测试：`i18n-shell.spec.ts`、`messages-isolation.spec.ts`、`i18n-constants.spec.ts`、`help-i18n.spec.ts`、core 的 `namespaces.spec.ts` / `engine.spec.ts` / `bundle.spec.ts` / `locale-keys.spec.ts`。
